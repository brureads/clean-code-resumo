INTRODUÇÃO

Conceitos fundamentais

Os princípios básicos do código limpo.

01 / INTRODUÇÃO

O que é Clean Code?

É a prática de escrever código claro, compreensível e fácil de manter.

Entenda melhor

Código limpo comunica sua intenção, evita complexidade desnecessária e facilita futuras alterações.

02 / NOMENCLATURA

Nomes significativos

Variáveis, classes e métodos devem ter nomes que expliquem sua finalidade.

Entenda melhor

Prefira nomes como totalCompra e CalcularDesconto em vez de nomes vagos como x ou abc.

03 / ORGANIZAÇÃO

Funções

Cada função deve ter uma finalidade bem definida.

Entenda melhor

Funções pequenas e coesas costumam ser mais fáceis de testar, entender e modificar.

APROFUNDAMENTO 02

Funções e métodos

Métodos simples e objetivos.

PRINCÍPIO 01

Responsabilidade única

Cada método deve ter uma tarefa definida.

Ver explicação

Evite misturar cálculos, apresentação de resultados e persistência de dados no mesmo método.

PRINCÍPIO 02

Funções pequenas

Prefira métodos curtos, claros e coesos.

Ver explicação

Não existe número mágico de linhas. O importante é evitar responsabilidades demais na mesma função.

PRINCÍPIO 03

Parâmetros

Evite listas excessivas de parâmetros.

Ver explicação

Muitos parâmetros dificultam testes e chamadas. Quando fizer sentido, agrupe dados relacionados.

EXEMPLO EM C#

Separando responsabilidades

ANTES — RESPONSABILIDADES MISTURADAS

Um método faz tudo

void MostrarTotal(
    decimal preco,
    int quantidade)
{
    decimal total =
        preco * quantidade;

    Console.WriteLine(
        $"Total: {total:C}");
}

O método calcula e apresenta o resultado.

DEPOIS — RESPONSABILIDADES SEPARADAS

Métodos com foco

decimal CalcularTotal(
    decimal preco,
    int quantidade)
{
    return preco * quantidade;
}

void MostrarTotal(decimal total)
{
    Console.WriteLine(
        $"Total: {total:C}");
}

decimal total =
    CalcularTotal(20m, 5);

MostrarTotal(total);

Cada método possui uma finalidade definida.

Por quê?

REGRA 02

Quando usar?

Para explicar regras de negócio, limitações externas e decisões importantes de implementação.

Comentários desatualizados podem confundir.

Entenda melhor

APROFUNDAMENTO 04

Formatação e organização

Uma boa estrutura facilita a leitura.

REGRA 01

Indentação

Use recuos consistentes nos blocos de código.

Entenda melhor

Os recuos facilitam reconhecer estruturas condicionais, loops, classes e métodos.

REGRA 02

Espaçamento

Separe visualmente partes relacionadas do código.

Entenda melhor

Espaços e linhas em branco ajudam a identificar grupos de instruções.

REGRA 03

Consistência

Siga os padrões de formatação do projeto.

Entenda melhor

Formatadores automáticos ajudam a manter um padrão em toda a equipe.

EXEMPLO EM C#

A importância da indentação

ANTES — FORMATAÇÃO CONFUSA

Difícil de ler

if (idade >= 18)
{
Console.WriteLine("Maior");
}
else
{
Console.WriteLine("Menor");
}

Os comandos não possuem recuos adequados.

DEPOIS — BOA INDENTAÇÃO

Mais legível

if (idade >= 18)
{
    Console.WriteLine("Maior");
}
else
{
    Console.WriteLine("Menor");
}

Os recuos deixam os blocos mais claros.

APROFUNDAMENTO 05

Tratamento de erros

Validação e tratamento de exceções em C#.

CONCEITO 01

Try e Catch

Permitem lidar com exceções na execução.

Entenda melhor

O try contém operações que podem lançar exceções. O catch permite capturar e tratar erros específicos.

CONCEITO 02

Finally

Executa ações de limpeza ao sair do try.

Entenda melhor

O bloco finally normalmente executa mesmo quando uma exceção acontece. É útil para ações de encerramento.

CONCEITO 03

Validação

Verifique dados antes de utilizá-los.

Entenda melhor

Validar entradas evita falhas previsíveis. Em C#, TryParse é útil para conversões seguras.

EXEMPLO EM C#

Validando uma conversão

ANTES — SEM VALIDAÇÃO

Pode lançar exceção

string entrada = "abc";

int idade = int.Parse(entrada);

Console.WriteLine(idade);

Parse lança exceção quando o texto não possui formato numérico válido.

DEPOIS — COM VALIDAÇÃO

Usando TryParse

string entrada = "abc";

if (int.TryParse(
    entrada,
    out int idade))
{
    Console.WriteLine(idade);
}
else
{
    Console.WriteLine(
        "Digite um número válido.");
}

TryParse permite verificar o resultado da conversão sem exceção por formato inválido.

EXEMPLO ADICIONAL

Try, Catch e Finally

try
{
    string conteudo =
        File.ReadAllText("dados.txt");

    Console.WriteLine(conteudo);
}
catch (FileNotFoundException)
{
    Console.WriteLine(
        "Arquivo não encontrado.");
}
finally
{
    Console.WriteLine(
        "Leitura encerrada.");
}

O catch trata especificamente um arquivo não encontrado. O finally executa a ação de encerramento, enquanto outras exceções podem continuar se propagando.
