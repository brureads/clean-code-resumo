01 / INTRODUÇÃO

O que é Clean Code?

É a prática de escrever código claro, compreensível e fácil de manter.

Entenda melhor

Um código limpo comunica sua intenção, evita complexidade desnecessária e facilita futuras alterações.

02 / NOMENCLATURA

Nomes significativos

Variáveis, classes e métodos devem ter nomes que expliquem sua finalidade.

Entenda melhor

Prefira nomes como totalCompra e CalcularDesconto em vez de nomes vagos como x ou abc.

03 / ORGANIZAÇÃO

Funções

Cada função deve ter uma finalidade bem definida.

Entenda melhor

Funções pequenas e coesas costumam ser mais fáceis de testar, entender e modificar.

APROFUNDAMENTO 02

Funções e métodos

Métodos simples e com objetivos claros.

PRINCÍPIO 01

Responsabilidade única

Cada método deve ter uma tarefa definida.

Ver explicação

Evite misturar cálculos, apresentação de resultados e persistência de dados no mesmo método.

PRINCÍPIO 02

Funções pequenas

Prefira métodos curtos, claros e coesos.

Ver explicação

Não existe número mágico de linhas. O objetivo é evitar responsabilidades demais na mesma função.

PRINCÍPIO 03

Parâmetros

Evite listas excessivas de parâmetros.

Ver explicação

Muitos parâmetros podem dificultar testes e chamadas. Quando fizer sentido, agrupe dados relacionados.

EXEMPLO EM C#

Separando responsabilidades

ANTES — RESPONSABILIDADES MISTURADAS

Um método faz tudo

void MostrarTotal(
    decimal preco,
    int quantidade)
{
    decimal total =
        preco * quantidade;

    Console.WriteLine(
        $"Total: {total:C}");
}

O método calcula e apresenta o resultado ao mesmo tempo.

DEPOIS — RESPONSABILIDADES SEPARADAS

Métodos com foco

decimal CalcularTotal(
    decimal preco,
    int quantidade)
{
    return preco * quantidade;
}

void MostrarTotal(decimal total)
{
    Console.WriteLine(
        $"Total: {total:C}");
}

decimal total =
    CalcularTotal(20m, 5);

MostrarTotal(total);

Agora cada método tem uma finalidade definida.

APROFUNDAMENTO 03

Comentários

Explique o necessário, evite o óbvio.

REGRA 01

Evite comentários óbvios

Não use comentários que apenas repetem o que o código já informa.

Por quê?

Eles aumentam a quantidade de texto sem acrescentar informação útil.

REGRA 02

Explique o motivo

Comentários podem ser úteis para explicar decisões que não são evidentes.

Quando usar?

Por exemplo, para documentar uma regra de negócio inesperada ou uma limitação externa relevante.

REGRA 03

Mantenha atualizado

Um comentário desatualizado pode confundir mais do que ajudar.

Entenda melhor

Ao alterar uma regra importante, revise os comentários relacionados. Remova os que perderam a utilidade.

EXEMPLO EM C#

Um comentário desnecessário

ANTES — COMENTÁRIO REDUNDANTE

Explicando o óbvio

// Soma um ao contador
contador = contador + 1;

O comentário apenas repete a operação escrita no código.

DEPOIS — CÓDIGO AUTOEXPLICATIVO

Clareza sem excesso

contador++;

A operação é simples e não precisa de explicação adicional.

APROFUNDAMENTO 04

Formatação e organização

Uma boa estrutura facilita a leitura.

REGRA 01

Indentação

Use recuos consistentes para deixar clara a estrutura do código.

Entenda melhor

Indentação facilita reconhecer blocos de if, loops, classes e métodos.

REGRA 02

Espaçamento

Use espaços e linhas em branco para separar ideias relacionadas.

Entenda melhor

Um código visualmente organizado é mais fácil de percorrer e revisar.

REGRA 03

Consistência

Siga os mesmos padrões de formatação em todo o projeto.

Entenda melhor

Utilize um formatador automático e respeite as convenções adotadas pela equipe.

EXEMPLO EM C#

A importância da indentação

ANTES — FORMATAÇÃO CONFUSA

Difícil de ler

if (idade >= 18)
{
Console.WriteLine("Maior");
}
else
{
Console.WriteLine("Menor");
}

Os comandos não estão visualmente alinhados aos seus blocos.

DEPOIS — BOA INDENTAÇÃO

Mais legível

if (idade >= 18)
{
    Console.WriteLine("Maior");
}
else
{
    Console.WriteLine("Menor");
}

O recuo evidencia quais instruções pertencem a cada bloco.
